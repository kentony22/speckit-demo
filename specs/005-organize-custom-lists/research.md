# Research — カスタムリスト

## 既存のパーティションで保存する

- **決定** — リスト文書を既存の `tasks` コンテナーの所有者パーティションに保存する。タスク文書に、そのリストを指す任意の項目を加える。
- **理由** — 既存のエミュレーター構成と Azure の無料枠を使える。移動はタスク文書の部分更新で済み、全件一覧の件数は維持される。
- **比較した案** — リストごとのタスク複製は更新の同期を必要とする。別コンテナーでは追加の環境設定とスループットの検証が必要となる。

## 文書と操作の境界

- **決定** — リスト文書には識別子 `kind` と `list-` で始まる ID を持たせる。未分類の旧タスクもタスク一覧に含める。リストの読み取りと部分更新は所有者のパーティション内で行う。
- **理由** — リスト文書をタスクとして表示したり、タスク更新で書き換えたりすることを防ぐ。旧データは移行なしで利用できる。
- **比較した案** — タスクごとにリスト名を持たせると、空のリストを表示できない。

## 画面の選択状態

- **決定** — 左側のリストは URL フラグメントで選択する。全件一覧は `#tasks`、リストは `#list-<UUID>` とする。全件を取得し、画面では選択した所属先だけを表示する。
- **理由** — ブラウザーの再読み込みと戻る・進む操作で一覧を開き直せる。既存の GET を他の機能でも再利用できる。
- **比較した案** — サーバー側の絞り込みは、この規模では一覧の再取得が増える。同じ操作で全件一覧と個別リストの結果を同期する必要もある。
