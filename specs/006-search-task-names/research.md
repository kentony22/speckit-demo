# Research: タスク名の検索

## 検索対象と表示順

- **決定** — `listTasks` で取得し、登録・更新時に同期する全タスクの状態を入力にして、相対順を維持したまま名前で絞り込む。
- **根拠** — 基準ブランチの GET は所有者の全タスクを返し、既存画面はその順で描画する。完了状態や所属リストは名前の照合に影響しない。
- **検討した案** — ビュー内の配列だけを絞り込むと別リストのタスクが漏れる。検索用 API は既存の全件取得と処理が重複する。

## 入力とビューの状態

- **決定** — クエリを React の独立した状態で保持し、全件と選択中のビューの一覧から表示を導出する。検索操作は URL ハッシュを更新しない。
- **根拠** — 基準ブランチは `#tasks` を使用する。統合時は `#important` と `#list-…` の既存ビューが選択した一覧を同じ処理に渡せる。
- **検討した案** — 検索専用ハッシュへ遷移する方法では復帰先の保存や履歴管理が増える。

## テスト

- **決定** — Node 標準ランナーで型付き検索モジュールを実行し、Chrome では基準機能で再現可能な操作を確認する。
- **根拠** — 最小のフィクスチャで別リストのタスクや重要ビューを再現できる。Node 26 は TypeScript の型を除去して実行できる。
- **検討した案** — 重要ビューとカスタムリストをこのブランチに仮実装すると担当範囲が重なる。実際のナビゲーションの受け入れ確認は統合後に行う。
