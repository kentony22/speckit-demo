# Feature Specification: タスクの登録と一覧表示

**Feature Branch**: `main`（仕様作成時）

**Created**: 2026-11-21

**Status**: Draft

**Input**: 個人ユーザーが画面下部の入力欄からタスクを登録し、同じ画面の一覧であとから確認できるようにする。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - タスクを登録してあとから確認する (Priority: P1)

個人ユーザーとして、覚えておきたいことをタスクとして登録し、ページを開き直したときに一覧で確認したい。

**Why this priority**: 登録した内容をあとから確認できることが、最初の機能でユーザーに提供する価値である。

**Independent Test**: タスクのない状態から画面を開き、画面下部の入力欄でタスク名を入力して Enter で1件追加し、同じ画面の一覧を確認してからページを再読み込みする。

**Acceptance Scenarios**:

1. **AC-001** — **前提** タスクが1件も登録されていない。**操作** タスク画面を開く。**期待結果** タスクが未登録であることを示すメッセージが表示される。
2. **AC-002** — **前提** タスク画面が開いている。**操作** 画面下部の入力欄に「牛乳を買う」と入力して Enter を押す。**期待結果** 同じ画面の一覧に「牛乳を買う」が1件追加される。
3. **AC-003** — **前提** 「牛乳を買う」が登録済みで一覧に表示されている。**操作** ページを再読み込みする。**期待結果** 一覧に「牛乳を買う」が引き続き1件表示される。
4. **AC-004** — **前提** タスク画面が開いている。**操作** 空欄または空白だけの状態で Enter を押す。**期待結果** 登録リクエストは送られず、エラー表示も一覧件数の変化もない。
5. **AC-005** — **前提** タスクを保存できない状態で、タスク画面が開いている。**操作** 有効な名前を入力して Enter を押す。**期待結果** 登録に失敗したことが表示され、一覧の件数は変わらない。

### Edge Cases

- 空欄または空白だけの入力では登録処理を開始しない（AC-004）。
- 追加時に保存に失敗した場合、登録成功時と区別できる表示にする（AC-005）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** — タスクが0件の場合、未登録であることを示すメッセージを表示する（AC-001）。
- **FR-002** — 画面下部の入力欄でタスク名を入力して Enter を押すと登録し、登録した名前を同じ画面の一覧に表示する（AC-002）。
- **FR-003** — 登録に成功したタスクを保存し、ページを再読み込みした後も一覧に表示する（AC-003）。
- **FR-004** — 空欄または空白だけの状態で Enter を押したときは、登録リクエストとエラー表示を行わない（AC-004）。
- **FR-005** — 保存に失敗したときは、失敗を画面に表示し、失敗したタスクを一覧に追加しない（AC-005）。

### Key Entities

- **タスク** — 一覧から確認できる、ユーザーが登録した1件の用事。登録に必要な情報はタスク名。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001** — 0件の状態で画面を1回開くと、ユーザーが未登録だと画面上で確認できる。
- **SC-002** — 有効な名前を1回追加すると、その名前が画面遷移なしで同じ一覧に1件増える。
- **SC-003** — 異なる名前で3件登録し、ページを1回再読み込みすると、3件すべてがそれぞれ1件ずつ一覧に表示される。

## Assumptions

- 初回デモは1人で使うタスク一覧を想定する。
- 今回の範囲は登録と一覧表示。編集、完了、重要の指定、カスタムリスト、検索は後続の機能とする。
- 未登録やエラーを示すメッセージの文言と、複数タスクの表示順は未確定。受け入れ条件は、メッセージで状態が伝わることと、登録された各タスクを確認できることを判定する。
