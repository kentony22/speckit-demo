# Feature Specification: タスクの重要指定

**Feature Branch**: `main`（仕様作成時）

**Created**: 2026-11-21

**Status**: Draft

**Input**: 一覧でタスクの重要マークを付け外しし、「重要」ビューで重要なタスクを確認できるようにする。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - タスクの重要指定 (Priority: P1)

個人ユーザーとして、優先して確認したい用事に目印を付けたい。

**Why this priority**: 元の一覧で優先して見たい用事を識別でき、「重要」ビューでまとめて確認できる。

**Independent Test**: タスク2件のうち1件を重要に指定し、元の一覧と「重要」ビューを確認する。再読み込みした後にマークを外し、元の一覧と「重要」ビューを再確認する。

**Acceptance Scenarios**:

1. **AC-001** — **前提** 重要指定のないタスクが2件ある。 **操作** 1件を重要に指定する。 **期待結果** その1件だけに元の一覧で重要マークが付き、「重要」ビューにも表示される。元の一覧の順序とタスクの完了状態が保たれる。
2. **AC-002** — **前提** 重要に指定されたタスクがある。 **操作** 指定を解除する。 **期待結果** 「重要」ビューから消え、元の一覧には引き続き表示される。タスクの完了状態は変わらない。
3. **AC-003** — **前提** 重要の指定または解除が保存された。 **操作** ページを再読み込みする。 **期待結果** 直前に保存した指定の有無が元の一覧のマークと「重要」ビューへの表示に反映される。
4. **AC-004** — **前提** 機能追加前のタスクがある。 **操作** 一覧を開き、そのタスクを重要に指定する。 **期待結果** 最初は未指定で、操作後は元の一覧と「重要」ビューに指定が反映される。
5. **AC-005** — **前提** 重要指定の変更を保存できない。 **操作** 指定または解除を試みる。 **期待結果** 失敗が表示され、最後に保存した状態から再試行できる。

### Edge Cases

- 重要状態が未記録の既存タスクは未指定として扱う（AC-004）。
- 保存に失敗しても直前の状態を表示する（AC-005）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** — 一覧から重要マークを付け外しできる。「重要」ビューに表示するのは指定済みのタスクとする。付け外しにかかわらず元の一覧に残り、順序と完了状態を維持する（AC-001、AC-002）。
- **FR-002** — 指定と解除を保存し、再読み込み後に元の一覧と「重要」ビューに最後の状態を表示する（AC-003）。
- **FR-003** — 重要状態を持たない既存タスクを未指定として表示する（AC-004）。
- **FR-004** — 保存できなかった場合は失敗を表示し、最後に保存した状態から再試行できるようにする（AC-005）。

### Key Entities

- **タスク** — 登録済みの用事。重要指定と完了状態を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001** — 2件のうち1件を1回の操作で重要に指定でき、元の一覧ではマーク付き1件を見分けられ、「重要」ビューでは指定した1件を確認できる。
- **SC-002** — 指定と解除の直後にそれぞれ1回再読み込みすると、「重要」ビューは1件、0件の順になる。元の一覧は2件のままで、完了状態も維持される。

## Assumptions

- [001-add-list-tasks](../001-add-list-tasks/spec.md) の一覧と [002-toggle-task-completion](../002-toggle-task-completion/spec.md) の完了状態を前提とする。どちらの完了状態でも重要を指定でき、新規タスクは未指定から始まる。
- 初回は一覧の重要マークと「重要」ビューを対象とする。優先度順の並べ替えは別機能とする。
