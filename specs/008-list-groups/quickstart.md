# Quickstart: リストグループ 確認手順

前提条件・ローカル起動手順は [README.md](../../README.md) を参照する。API 契約は [contracts/list-groups.md](contracts/list-groups.md)、データ条件は [data-model.md](data-model.md) を参照する。

## 1. 自動テストとビルド

```bash
# フロントエンドのテスト・型チェック・ビルド
cd frontend && npm test && npm run build

# バックエンドの単体テストおよび Cosmos DB vNext エミュレーター結合テスト
docker compose up -d
./scripts/prepare-local-cosmos.sh
cd backend
JAVA_TOOL_OPTIONS="-Djavax.net.ssl.trustStore=\"$PWD/../.local/cosmos.p12\" -Djavax.net.ssl.trustStorePassword=changeit" \
    ./mvnw -B -ntp verify
```

## 2. ブラウザーでの受け入れ確認

専用所有者 ID（例: `TODO_OWNER_ID=group-check-1`）でアプリを起動し、カスタムリスト2件とタスク1件を用意して確認する。

| 条件 | 操作 | 期待結果 |
| --- | --- | --- |
| AC-001 | 左側のグループ作成フォームから「プライベート」「キャリア」を作成し、見出しをクリックして折りたたみ・展開を切り替える | 両グループが左側に表示され開閉できる。空のグループを展開すると未所属であることが分かる |
| AC-005 | 空欄・半角空白・全角空白でグループ作成を試みる | 入力エラーが表示され、グループは作成されない |
| AC-002 / SC-001 | カスタムリスト1件を開き、グループを「プライベート」へ変更後、「キャリア」へ移動する | 所属グループ配下のみに表示され重複しない。移動後は「プライベート」から消えて「キャリア」に表示される |
| AC-003 / SC-002 | ページを再読み込みし、「キャリア」配下のカスタムリストを開く | グループ・リスト所属・リスト内のタスク、すべてのタスク・重要・検索がすべて保持される |
| AC-004 | カスタムリストのグループを「グループなし」へ変更する | グループ配下から外れて未分類リスト欄に戻り、リスト内のタスクは維持される |
| AC-006 | API が `503` を返す状態でグループ作成・名前変更または所属変更を試し、復旧後に再試行する | 失敗メッセージが表示され直前の状態と入力が保たれ、再試行で成功する |
| AC-007 | グループの「編集」から新しい名前を保存して再読み込みし、またキャンセルおよび空白入力を試す | 新しい名前がサイドバーとグループ選択欄に反映され再読み込み後も維持される。キャンセルと空白入力では元の名前が保たれる |
