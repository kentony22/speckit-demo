# Feature Specification: リストグループ

**Feature Branch**: `feature/008-list-groups`

**Created**: 2026-11-21

**Status**: Draft

**Input**: User description: "サイドバーのリストグループ機能（カスタムリストをグループにまとめて開閉できる機能）を追加する。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - リストグループ (Priority: P1)

個人ユーザーとして、「プライベート」「キャリア」のように複数のカスタムリストをグループにまとめて折りたたみ・展開し、増えたカスタムリストを画面左側で整理したい。

**Why this priority**: カスタムリストが増えても用途別のグループに束ねて開閉できることで、目的のリストを素早く見つけられるため。

**Independent Test**: グループ2件とカスタムリスト2件を用意し、グループ作成・名前変更・削除（確認とキャンセル、配下リストの未分類化）・開閉、リストの割り当て・別グループへの移動・解除、再読み込み後の状態維持、空白入力エラー、保存失敗からの再試行を単独で確認できる。

**Acceptance Scenarios**:

1. **AC-001** — **前提** 画面左側のナビゲーションを表示している。 **操作** 空白以外を含む名前でリストグループを作成し、グループの見出しを選択して折りたたみ・展開を切り替える。 **期待結果** 作成したグループが画面左側に表示され、見出し操作で開閉できる。リストが属していないグループを開くと未所属であることが分かる。
2. **AC-002** — **前提** グループ2件とカスタムリスト2件がある。 **操作** カスタムリスト1件を最初のグループに割り当て、続いてもう一方のグループへ移動する。 **期待結果** 割り当てたリストは最初のグループ配下に表示され、未分類リスト欄には重複表示されない。移動後は最初のグループから消えて移動先グループ配下に表示される。
3. **AC-003** — **前提** グループにカスタムリストが割り当てられており、そのリストにタスクが属している。 **操作** ページを再読み込みし、グループ配下のカスタムリストを開く。 **期待結果** グループと各リストの所属が保たれ、リスト内のタスク、すべてのタスク、重要ビュー、検索がいずれも正しく表示される。
4. **AC-004** — **前提** カスタムリストがグループに割り当てられている。 **操作** そのリストのグループ割り当てを解除する。 **期待結果** グループ配下から外れて未分類のカスタムリスト一覧に戻り、リスト内のタスクはそのまま維持される。
5. **AC-005** — **前提** リストグループを作成しようとしている。 **操作** 空欄、半角空白だけ、全角空白だけのいずれかで作成を試みる。 **期待結果** 入力エラーが表示され、グループは作成されない。
6. **AC-006** — **前提** グループの作成、グループ名の変更、グループの削除、またはリストのグループ変更を保存できない状態である。 **操作** 作成・変更・削除を試みる。 **期待結果** 失敗メッセージが表示され、直前の保存状態と編集中の入力を維持したまま再試行できる。
7. **AC-007** — **前提** 作成済みのリストグループがあり、配下にカスタムリストが属している。 **操作** グループ名を空白以外を含む新しい名前へ変更して保存し、ページを再読み込みする。また、編集中にキャンセルおよび空欄・空白だけの保存を試みる。 **期待結果** 新しいグループ名が画面左側と所属選択欄に反映され、再読み込み後も保たれ、配下のカスタムリストとタスクは維持される。キャンセルおよび空白だけの入力では元のグループ名が維持される。
8. **AC-008** — **前提** 作成済みのリストグループが2件あり、一方の配下にカスタムリストとタスクが属している。 **操作** 削除確認を開いてキャンセルした後、再度削除を確定し、ページを再読み込みする。 **期待結果** キャンセル時はグループと配下リストがそのまま維持される。削除確定後は対象グループだけが消え、配下にあったカスタムリストは未分類リストとして左側一覧に残り、リスト内のタスクと他グループは維持される。再読み込み後も削除済みグループは再表示されず、未分類になったリストとタスクを確認できる。

### Edge Cases

- リストが1件も属さない空のグループは、展開時に「リストはまだありません。」等のように空であることが分かり、そのまま削除もできる（AC-001、AC-008）。
- グループに属さない既存のカスタムリスト（旧データ含む）は未分類のカスタムリストとしてそのまま選択・利用できる（AC-003、AC-004）。
- 折りたたんだグループ配下のカスタムリストを URL ハッシュで直接開いた場合でも、該当リストのタスク一覧を表示でき、必要に応じてグループを展開して確認できる。
- 削除対象グループ配下のカスタムリストを開いている状態でグループを削除しても、表示中のリストとタスクはそのまま維持される（AC-008）。
- 存在しないグループや別所有者のグループへの割り当て・名前変更・削除、あるいはタスク・カスタムリストに対するグループ削除や、タスク・グループ自身に対するリスト移動操作は拒否され、既存データは変化しない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** — 空白以外を含む名前でリストグループを作成し、画面左側に表示できる。空欄・空白だけの場合は入力エラーを表示して作成しない（AC-001、AC-005）。
- **FR-002** — 画面左側の各リストグループを見出し操作で折りたたみ・展開でき、展開時は所属するカスタムリストを一覧表示し、0件のときは空と分かる表示にする（AC-001）。
- **FR-003** — 各カスタムリストを最大1件のリストグループに割り当て、別グループへ移動し、または未分類へ解除できる。割り当てたリストは所属グループ配下にのみ表示し、重複表示しない（AC-002、AC-004）。
- **FR-004** — 作成したグループと各カスタムリストのグループ所属を永続化し、再読み込み後も復元する。既存のタスク表示・編集・完了・重要・削除・検索の動作を維持する（AC-003）。
- **FR-005** — グループの作成・名前変更・削除やリストの所属変更を保存できない場合は失敗メッセージを表示し、最後の保存状態と編集中の入力を保ったまま再試行できるようにする（AC-006）。
- **FR-006** — 既存のリストグループの名前を空白以外を含む新しい名前に変更して永続化でき、配下のカスタムリストとタスクを維持する。キャンセルや空欄・空白だけの入力では元の名前を維持する（AC-007）。
- **FR-007** — 既存のリストグループを確認ステップ付きで削除でき、キャンセル時は削除せず維持する。削除確定時は対象グループのみを取り除き、配下のカスタムリストは未分類として残したまま永続化し、所属タスクと他グループを維持する（AC-008）。

### Key Entities *(include if feature involves data)*

- **リストグループ** — 複数のカスタムリストを束ねる名前付きの分類単位。0件以上のカスタムリストを含む。
- **カスタムリスト** — タスクを分類する一覧。任意で最大1件のリストグループに所属する。
- **タスク** — 既存の用事。所属カスタムリスト経由で整理され、グループ変更によってタスク自体は変化しない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001** — グループ2件とリスト2件で、割り当て・移動・解除の各操作ごとに各グループおよび未分類欄のリスト件数が100%一致し、重複表示が0件である。
- **SC-002** — 割り当て・移動・グループ名変更・グループ削除の後にページを1回再読み込みしても、残存するすべてのグループ名と各リストの所属（削除されたグループ配下の未分類化を含む）が復元され、所属リスト内のタスクが100%保持される。
- **SC-003** — 空欄・半角空白・全角空白の3パターンのグループ作成および名前変更試行すべてで保存が行われず入力エラーが表示され、編集キャンセル1回および削除確認キャンセル1回のいずれでも元のグループと所属リストが100%維持される。

## Assumptions

- [005-organize-custom-lists](../005-organize-custom-lists/spec.md) のカスタムリストを前提とし、既存カスタムリストは未分類（グループ未所属）として扱う。
- 今回はグループの作成・名前変更・削除・折りたたみ／展開・カスタムリストのグループ割り当て／移動／解除を対象とする。グループの入れ子（階層化）は別機能とする。
- グループを削除しても配下のカスタムリストやタスクは削除せず、カスタムリストを未分類（グループ未所属）へ戻す。誤操作防止のため削除確定前に1段階の確認ステップ（確定／キャンセル）を設ける。
- グループの開閉状態は画面上の表示状態として扱い、初期表示時は展開状態とする。
