# Quickstart: カスタムリストの削除 確認手順

前提条件・ローカル起動手順は [README.md](../../README.md) を参照する。API 契約は [contracts/delete-task-list.md](contracts/delete-task-list.md)、データ条件は [data-model.md](data-model.md) を参照する。

## 1. 自動テストとビルド

```bash
# フロントエンドのテスト・型チェック・ビルド
cd frontend && npm test && npm run build

# バックエンドの単体テストおよび Cosmos DB vNext エミュレーター結合テスト
docker compose up -d
./scripts/prepare-local-cosmos.sh
cd backend
JAVA_TOOL_OPTIONS="-Djavax.net.ssl.trustStore=\"$PWD/../.local/cosmos.p12\" -Djavax.net.ssl.trustStorePassword=changeit" \
    ./mvnw -B -ntp verify -Pbundled-web
```

## 2. ブラウザーでの受け入れ確認

専用所有者 ID（例: `TODO_OWNER_ID=delete-list-check-1`）でアプリを起動し、リストグループ1件・カスタムリスト2件（「買い物」「仕事」、うち1件はグループ配下）・各リストに所属するタスクを用意して確認する。

| 条件 | 操作 | 期待結果 |
| --- | --- | --- |
| AC-004 / SC-002 | カスタムリスト「買い物」のゴミ箱アイコンを押し、確認パネルで「キャンセル」を押す | 確認パネルが閉じ、「買い物」リスト・グループ所属・所属タスクがすべて維持される。再読み込み後も変化しない |
| AC-001 / SC-001 | 「タスク」表示中に「買い物」のゴミ箱アイコン →「削除する」を押す | 「買い物」だけが左ナビゲーションから消え、「仕事」とグループは維持される。「買い物」に所属していたタスクは削除されず「リストなし」で「タスク」に残る |
| AC-002 / SC-003 | カスタムリスト「仕事」を開いて表示中に「仕事」のゴミ箱アイコン →「削除する」を押す | 画面が自然に「タスク」（`#tasks`）へ戻り、「仕事」に所属していたタスクが「リストなし」状態で一覧に残る。グループ自体は維持される |
| AC-003 / SC-001 | ページを再読み込みする | 削除したカスタムリストは再表示されず、元の所属タスクが「リストなし」状態（名前・完了・重要を維持）で「タスク」に残る |
| AC-005 | エミュレーター停止など `503` が返る状態でカスタムリスト削除を確定し、復旧後に再試行する | 確認パネルに失敗メッセージが表示され、リストと所属タスクは維持される。復旧後の再試行で削除が完了する |
