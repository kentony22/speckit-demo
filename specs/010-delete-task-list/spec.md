# Feature Specification: カスタムリストの削除

**Feature Branch**: `feature/010-delete-task-list`

**Created**: 2026-11-21

**Status**: Draft

**Input**: User description: "カスタムリストを削除できる機能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - カスタムリストの削除 (Priority: P1)

個人ユーザーとして、不要になったカスタムリストを確認ステップ付きで削除し、所属していたタスクを失うことなく画面左側のリスト一覧をすっきり整理したい。

**Why this priority**: 使い終えたカスタムリストを削除できないとリストが増え続け、必要な一覧を見つけにくくなるため。また、リストを削除しても所属していたタスク自体は残るようにすることで、安心してリストを整理できるため。

**Independent Test**: カスタムリスト2件・リストグループ1件・各リストに所属するタスクを用意し、確認ステップ付きの削除確定、所属タスクが「リストなし」として「すべてのタスク」に残ること、表示中リスト削除時の「すべてのタスク」への遷移、再読み込み後の状態維持、キャンセル時の維持、削除失敗時の維持と再試行を単独で確認できる。

**Acceptance Scenarios**:

1. **AC-001** — **前提** カスタムリストが2件あり、削除対象のリストにタスクが所属している。 **操作** 対象リストの削除操作を開始し、確認ステップで削除を確定する。 **期待結果** 選んだカスタムリストだけがナビゲーションとタスクの所属先候補から消え、もう一方のカスタムリストやリストグループは維持される。削除したリストに所属していたタスク自体は削除されず、「リストなし」の状態になって「すべてのタスク」に残る（タスク名・完了・重要の状態も維持される）。
2. **AC-002** — **前提** 削除対象のカスタムリストを現在表示している。 **操作** そのカスタムリストの削除を確認・確定する。 **期待結果** 画面は自然に「すべてのタスク」の一覧へ戻り、削除したリストに所属していたタスクを含む残りのタスクが表示される。残りのカスタムリストとリストグループも維持される。
3. **AC-003** — **前提** カスタムリスト1件の削除が確定された。 **操作** ページを再読み込みする。 **期待結果** 削除したカスタムリストは再表示されず、残りのカスタムリスト・リストグループと、元のリストに所属していたタスク（「リストなし」状態）が保持される。
4. **AC-004** — **前提** カスタムリスト削除の確認ステップが表示されている。 **操作** 削除をキャンセルする。 **期待結果** 確認表示が閉じ、対象のカスタムリスト・そのグループ所属・所属タスクの割り当てはいずれも変化せず維持される。
5. **AC-005** — **前提** 削除を保存できない状態である。 **操作** カスタムリストの削除を確定する。 **期待結果** 削除失敗メッセージが表示され、対象のカスタムリストと所属タスクは削除前の状態のまま維持され、復旧後に再試行して削除できる。

### Edge Cases

- グループに所属しているカスタムリストを削除しても、所属先グループ自体は削除されず、同じグループ内の他のカスタムリストも維持される（配下のリストが0件になった場合は空のグループ表示になる）。
- タスクが1件も所属していない空のカスタムリストも同様に削除できる。
- 削除対象とは別のビュー（「すべてのタスク」「重要」または別のカスタムリスト）を表示中に削除した場合は、現在の表示ビューを維持したまま対象リストだけが取り除かれ、該当タスクの所属先も「リストなし」に更新される。
- 確認ステップ中にキャンセルした場合は削除を実行しない（AC-004）。
- 削除に失敗した場合でも対象リストと所属タスクは維持され、再試行で削除できる（AC-005）。
- 存在しないカスタムリスト、カスタムリスト以外のデータ（タスクやリストグループ等）、または別所有者のリストを誤って削除対象にしても、既存のタスク・カスタムリスト・リストグループは影響を受けない。
- 削除確定操作の連打や二重送信が発生しても、意図しない別リストやタスクの削除は起きない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** — 各カスタムリストに対して削除操作を提供し、確認ステップを経て選択した1件だけを削除する。他のカスタムリストおよびリストグループは維持する（AC-001）。
- **FR-002** — カスタムリストを削除する際、そのリストに所属していたタスク自体は削除せず「リストなし」の状態に戻し、タスク名・完了・重要の状態を保ったまま「すべてのタスク」に残す（AC-001）。
- **FR-003** — 削除を確定する前に1段階の確認ステップ（確定／キャンセル）を設け、キャンセルした場合は削除を行わず対象リストと所属タスクを維持する（AC-004）。
- **FR-004** — 現在表示中のカスタムリストを削除した場合は「すべてのタスク」へ自然に戻し、別のビューを表示中に削除した場合は現在の表示ビューを維持する（AC-002）。
- **FR-005** — カスタムリストの削除と所属タスクの「リストなし」への戻しを永続化し、ページを再読み込みしても削除済みリストを再表示せず、タスクを保持する（AC-003）。
- **FR-006** — 削除を完了できない場合は失敗メッセージを表示し、対象リストと所属タスクを削除前の状態に保ったまま再試行できるようにする（AC-005）。

### Key Entities *(include if feature involves data)*

- **カスタムリスト** — タスクを分類する名前付きの一覧。削除操作により1件単位で取り除かれる。
- **タスク** — 登録済みの用事。所属していたカスタムリストが削除されてもタスク自体は削除されず、所属先が「リストなし」に戻る。
- **リストグループ** — カスタムリストを束ねる分類単位。配下のカスタムリストが削除されてもリストグループ自体は保持される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001** — カスタムリスト2件から選んだ1件を2操作以内（削除開始と確定）で削除でき、1回の再読み込み後も削除済みリストが再表示されず、所属していたタスクの100%が「リストなし」状態で「すべてのタスク」に保持される。
- **SC-002** — 確認ステップからのキャンセル操作1回で、対象のカスタムリスト・グループ所属・所属タスクの割り当てが一覧および再読み込み後の両方で100%保持される。
- **SC-003** — 削除対象のカスタムリストを表示中に削除を確定した直後に、エラー画面や不正な表示にならず100%「すべてのタスク」へ自然に戻る。

## Assumptions

- [005-organize-custom-lists](../005-organize-custom-lists/spec.md)、[007-delete-task](../007-delete-task/spec.md)、[008-list-groups](../008-list-groups/spec.md) のカスタムリスト・タスク削除・リストグループを前提とする。
- 今回はカスタムリスト1件の削除を対象とする。削除の取り消し（Undo）、ゴミ箱、複数リストの一括削除、カスタムリストの名前変更、およびリストグループ自体の削除は別機能とする。
- 誤削除を防ぐため、削除確定前に1段階の確認ステップ（確定／キャンセル）を設け、削除しても所属タスク自体は残ることが利用者に伝わる表現にする。
