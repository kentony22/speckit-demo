## フェーズ3 — US1 一覧からタスクの状態を切り替える

**ゴール** — 既存タスクと新規タスクを一覧で完了・未完了にでき、最後に保存した状態が再読み込み後も表示される。

**独立した確認** — 旧形式のタスク1件と新規タスク1件を使い、旧形式の1件だけを完了にする。再読み込み後に完了済みと確認し、未完了に戻して再読み込みする。もう1件の状態、一覧の件数と順序も確認する。

### 1. Spring Boot API と Cosmos DB

- [X] T003 [P] [US1] `backend/src/test/java/com/example/todo/tasks/TaskControllerTest.java` に PATCH の REST テストを追加する。真偽値の両方向で 200、欠落・`null`・文字列・数値で 400、対象なしで 404、保存失敗で 503 を検証し、GET と POST の既存契約と `completed` の応答も確認する。依存 T002。
- [X] T004 [P] [US1] `backend/src/test/java/com/example/todo/tasks/TasksCosmosIT.java` で、テスト専用の所有者パーティションに `completed` のない旧形式 JSON を直接投入する。GET で未完了、PATCH と別の GET で完了・未完了が保存されること、同じ値の再送で反転しないこと、ID・名前・作成日時・所有者が維持されることを検証する。別パーティションにだけある ID の PATCH は 404 とし、作成したテストデータを片付ける。依存 T002。
- [X] T005 [US1] `backend/src/main/java/com/example/todo/tasks/TaskDocument.java` に `completed` を追加し、旧形式の欠落または `null` を未完了として扱えるようにする。依存 T003、T004。
- [X] T006 [US1] `backend/src/main/java/com/example/todo/tasks/CosmosTaskRepository.java` で、新規タスクを未完了として保存し、既存のパーティションキーとタスク ID で `patchItem` を実行する。 `set("/completed", value)` で状態だけを更新し、保存後の文書を返す。依存 T005。
- [X] T007 [US1] `backend/src/main/java/com/example/todo/tasks/TaskController.java` に `PATCH /api/tasks/{id}` を実装する。本文の `completed` は JSON の真偽値に限定し、200・400・404・503 を計画に合わせる。GET と POST の応答にも必ず真偽値を含め、既存の要求形式とステータスを維持する。依存 T006。
- [X] T008 [US1] `backend/pom.xml` の Maven Wrapper 構成で `./mvnw -B -ntp verify` を実行する。T003・T004 と既存の登録・一覧テストをエミュレーター接続込みで通す。依存 T007。

**完了条件** — 旧形式のタスクを未完了として取得でき、両方向の変更が別の GET に反映される。新規登録と既存の一覧取得も通る。
