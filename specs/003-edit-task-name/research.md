# 設計判断

- 名前の更新は `PATCH /api/tasks/{id}/name` とする。既存の完了 API を呼ぶ利用者との互換性を保ち、入力の責務を分ける。既存 PATCH に更新項目の判定を足す案も検討した。
- Cosmos DB では完了更新と同じ方法を再利用し、`/name` のみ設定する。文書全体の置換では、別の操作が保存した変更を上書きする可能性がある。
- React では編集中の文字列と保存済みの名前を分け、応答に含まれる名前だけを一覧へ反映する。保存前に一覧を書き換える案では、エラー時に表示を戻す処理が必要になる。
- 既存の入力と同じ空白判定を使い、編集中の空白だけの入力にはエラーを表示する。前後の空白を削る案も検討したが、登録と編集で保存される文字列をそろえる。
