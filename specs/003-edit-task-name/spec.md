# Feature Specification: タスク名の編集

**Feature Branch**: `main`（仕様作成時）

**Created**: 2026-11-21

**Status**: Draft

**Input**: 一覧から登録済みタスクの名前を修正する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - タスク名の編集 (Priority: P1)

個人ユーザーとして、入力ミスや用事の変更に合わせて、登録済みの名前を修正したい。

**Why this priority**: 登録し直す手間を省き、一覧を最新に保てる。

**Independent Test**: タスク2件のうち1件を編集し、保存、再読み込み、キャンセルを確認する。

**Acceptance Scenarios**:

1. **AC-001** — **前提** 登録済みのタスクが2件ある。 **操作** 1件を選び、空白以外を含む新しい名前を保存する。 **期待結果** 選んだ1件だけが新しい名前で表示され、完了状態と一覧の件数は維持される。
2. **AC-002** — **前提** 名前の変更が保存された。 **操作** ページを再読み込みする。 **期待結果** 同じタスクが変更後の名前で表示される。
3. **AC-003** — **前提** タスク名を編集中である。 **操作** 名前を変更してキャンセルする。 **期待結果** 編集を閉じ、元の名前のまま一覧に戻る。
4. **AC-004** — **前提** タスク名を編集中である。 **操作** 名前を空欄、半角空白だけ、全角空白だけのいずれかにして保存を試みる。 **期待結果** 入力エラーが表示され、元の名前が維持される。
5. **AC-005** — **前提** 名前を保存できない状態である。 **操作** 有効な名前で保存を試みる。 **期待結果** 失敗が表示され、保存済みの名前と再試行に使う入力が保たれる。

### Edge Cases

- 空欄、半角空白だけ、全角空白だけは保存不可とする（AC-004）。
- 保存に失敗しても編集中の入力を保持する（AC-005）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** — 対象のタスク名を変更し、件数と完了状態を維持する。保存した名前は再読み込み後も表示する（AC-001、AC-002）。
- **FR-002** — 編集をキャンセルすると、保存済みの名前のまま一覧に戻る（AC-003）。
- **FR-003** — 空欄・空白だけの入力では保存を行わず、入力エラーを表示する（AC-004）。
- **FR-004** — 保存できない場合は失敗を表示し、保存済みの名前と再試行用の入力を保持する（AC-005）。

### Key Entities

- **タスク** — 登録済みの用事。編集対象はタスク名。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001** — 2件から選んだ1件だけを1回の保存で変更でき、1回の再読み込み後も変更後の名前で見つけられる。
- **SC-002** — キャンセル1回と、空欄・半角空白・全角空白での3回の保存操作のそれぞれで、保存済みの名前が維持される。

## Assumptions

- [001-add-list-tasks](../001-add-list-tasks/spec.md) の登録・一覧と [002-toggle-task-completion](../002-toggle-task-completion/spec.md) の完了状態を前提とする。完了済みのタスクも編集できる。
- 初回はタスク名の編集を対象とする。期限やメモの追加、削除は別機能とする。
